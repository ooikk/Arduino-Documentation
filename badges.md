## URL Anatomy

Shields.io static badges use the base URL `https://img.shields.io/badge/` followed by a **path segment** and optional **query parameters**.

### Path Form (recommended for simple badges)

```
https://img.shields.io/badge/<label>-<message>-<color>
```

Example:

```
https://img.shields.io/badge/build-passing-brightgreen
```

### Query Form (recommended when overriding defaults)

```
https://img.shields.io/badge/<label>-<message>-<color>?<param>=<value>&<param>=<value>
```

Example:

```
https://img.shields.io/badge/build-passing-brightgreen?style=for-the-badge&logo=github
```

### Message-Only Form

You can omit the label and pass just a message + color:

```
https://img.shields.io/badge/just%20the%20message-8A2BE2
```

This produces a single-section badge with no left-hand label.

## Path Encoding Rules

Since label, message, and color are embedded in the URL path, special characters must be encoded using these rules:

| URL Input | Badge Output | Example |
|---|---|---|
| Underscore `_` | Space ` ` | `build_passing` → `build passing` |
| Double underscore `__` | Underscore `_` | `node__js` → `node_js` |
| Double dash `--` | Dash `-` | `v1--0--0` → `v1-0-0` |
| `%20` | Space ` ` | `just%20the%20message` → `just the message` |
| `%25` | Percent `%` | `95%25` → `95%` |

**Key takeaway:** Use `_` for spaces in the path. Use `--` when you need a literal hyphen in your label or message text. Never put a raw `%` in the path — always use `%25`.

## Parameter Reference Table

All parameters are passed as **query string** arguments after the `?` in the URL.

| Parameter | Type | Description | Default | Example |
|---|---|---|---|---|
| `label` | string | Overrides the left-hand-side text (the label from the path). URL-encode spaces. | From path | `?label=healthiness` |
| `labelColor` | string | Background color of the left (label) part. Accepts hex, rgb, rgba, hsl, hsla, CSS named colors. | `grey` (#555) | `?labelColor=abcdef` |
| `color` | string | Background color of the right (message) part. Same formats as `labelColor`. | From path (endpoint badges default to `lightgrey` #9f9f9f) | `?color=fedcba` |
| `style` | string | Badge template style. Values: `flat`, `flat-square`, `plastic`, `for-the-badge`, `social`. | `flat` | `?style=for-the-badge` |
| `logo` | string | Icon slug from [Simple Icons](https://simpleicons.org), or a custom base64 data URI. | none | `?logo=github` |
| `logoColor` | string | Color of the logo. Same color formats. **Simple Icons logos only — not custom logos.** | none | `?logoColor=violet` |
| `logoSize` | string | Set to `auto` for adaptive resizing of wide logos (e.g. `amd`, `amg`). **Simple Icons logos only.** | none | `?logoSize=auto` |
| `link` | string\[\] | Click targets for the left and right sides of the badge. Pass multiple `link=` params. **Only works in `<object>` HTML tags — not `<img>` or Markdown.** | none | `?link=https://left&link=https://right` |
| `cacheSeconds` | string | HTTP cache lifetime in seconds. Values below the default are ignored. | Auto-inferred | `?cacheSeconds=3600` |

### Legacy Parameter Aliases

These older parameter names still work but are deprecated in favor of the ones above:

| Legacy | Current | Notes |
|---|---|---|
| `colorA` | `labelColor` | Left-side background color |
| `colorB` | `color` | Right-side background color |

## Colors

### Supported Color Formats

All color parameters (`color`, `labelColor`, `logoColor`) accept the following formats:

| Format | Example (in URL) | Notes |
|---|---|---|
| Hex (3-digit) | `4c1` | Omit the `#` |
| Hex (6-digit) | `007ec6` | Omit the `#` |
| Hex with `#` | `%23007ec6` | URL-encode `#` as `%23` — or just omit `#` |
| `rgb()` | `rgb(46,164,79)` | Commas and spaces work in query string |
| `rgba()` | `rgba(46,164,79,0.5)` | Alpha channel supported |
| `hsl()` | `hsl(270,60%,70%)` | URL-encode: `hsl%28270%2C60%25%2C70%25%29` |
| `hsla()` | `hsla(270,60%,70%,0.5)` | Same encoding as `hsl` |
| CSS named color | `orange`, `violet` | See [Named Color Table](#named-color-table) below |
| Shields named color | `brightgreen` | See [Named Color Table](#named-color-table) below |

### Hex Color Rules

- **Omit the `#` prefix.** This is the simplest and most common approach: `color=007ec6`
- If you include `#`, you **must** URL-encode it as `%23`: `color=%23007ec6`
- Both 3-digit (`4c1`) and 6-digit (`44cc11`) forms are accepted
- Hex is case-insensitive: `ABCDEF` = `abcdef`

### RGB / HSL Encoding

When using `rgb()`, `rgba()`, `hsl()`, or `hsla()` in the **path segment**, you must URL-encode parentheses, commas, and percent signs:

| Raw | URL-Encoded |
|---|---|
| `(` | `%28` |
| `)` | `%29` |
| `,` | `%2C` |
| `%` | `%25` |
| ` ` (space) | `%20` |

Example — `rgb(46,164,79)` in the path: `rgb%2846%2C164%2C79%29`

Example — `hsl(270,60%,70%)` in the path: `hsl%28270%2C60%25%2C70%25%29`

In the **query string**, these characters are often tolerated without encoding, but encoding them is safest.

## Named Color Table

These are the built-in Shields.io named colors with their hex values, as defined in the [badge-maker source code](https://github.com/badges/shields/issues/11261):

| Named Color | Hex | Common Use |
|---|---|---|
| `brightgreen` | `#4c1` | Passing, success, MIT license |
| `green` | `#97CA00` | Active, maintained |
| `yellowgreen` | `#a4a61d` | Warning-ish |
| `yellow` | `#dfb317` | Caution, pending |
| `orange` | `#fe7d37` | Warning, attention |
| `red` | `#e05d44` | Failure, error, deprecated |
| `blue` | `#007ec6` | Informational, version |
| `grey` | `#555` | Default label color |
| `lightgrey` | `#9f9f9f` | Default message color, neutral, inactive |

**Note:** Some of these named colors differ from their CSS color values. For example, CSS `orange` is `#ffa500` but Shields `orange` is `#fe7d37`. Always use the Shields named color table above, or specify an explicit hex value if you need CSS-exact colors.

## Custom Base64 Logos

You can pass any custom SVG (or PNG) as a logo by base64-encoding it and using a [data URI](https://developer.mozilla.org/en-US/docs/Web/HTTP/Basics_of_HTTP/Data_URIs) in the `logo` parameter.

### Syntax

```
?logo=data:image/svg+xml;base64,<base64-encoded-SVG>
```

**Important:** The `+` in `image/svg+xml` must be URL-encoded as `%2b`:

```
?logo=data:image/svg%2bxml;base64,<base64-encoded-SVG>
```

### How to Create a Custom Logo

1. **Get an SVG** of your logo. PNG also works but SVG is preferred for crisp rendering.
2. **Optimize the SVG** using a tool like [SVGOMG](https://jakearchibald.github.io/svgomg/) to reduce file size.
3. **Base64-encode** the SVG content using any base64 encoder (e.g., `base64` CLI, [base64-image.de](https://www.base64-image.de/), or an online converter).
4. **URL-encode** the data URI if needed — at minimum, encode `+` as `%2b`.
5. **Append to the badge URL** as `?logo=data:image/svg%2bxml;base64,...`.

#### Command-Line Example (Linux/macOS)

```bash
# Encode an SVG file to base64
base64 -w 0 logo.svg

# Or as a one-liner that builds the full badge URL
echo "https://img.shields.io/badge/my-project-blue?logo=data:image/svg%2bxml;base64,$(base64 -w 0 logo.svg)"
```

### Size Limit

There is a **limit of 8192 bytes** on the total request header size. This means the base64-encoded logo text must be slightly under 8192 bytes, depending on the rest of the URL. Keep your SVGs small and optimized.

### Custom Logo Limitations

- `logoColor` does **not** work with custom base64 logos — it only works with Simple Icons named logos.
- `logoSize=auto` does **not** work with custom base64 logos either.
- Pre-size your SVG (e.g., set `width` and `height` attributes) before encoding if you need a specific size.

## Link Targets (Left / Right Click)

The `link` parameter makes the left and right sides of a badge independently clickable. It accepts an array of URLs, passed as repeated query parameters:

```
?link=https://left-target.com&link=https://right-target.com
```

- The **first** `link=` sets the left-side (label) click target.
- The **second** `link=` sets the right-side (message) click target.

### Critical Limitation: Only Works in `<object>` Tags (Not in GitHub READMEs)

The `link` parameter **only works when the badge is embedded in an `<object>` HTML tag**. It does **not** work with:

- `<img>` tags
- Markdown image syntax `![](...)`
- Any other markup language

**Important for GitHub READMEs:** GitHub's Markdown sanitizer strips or neuters `<object>` tags, so split click targets are **not reliably available** in GitHub README files. Use a single outer link instead (see below).

This is because the clickable areas are SVG `<a>` elements embedded inside the SVG output, and `<img>` tags do not support interactive SVG links.

#### Working Example (HTML `<object>` tag)

```html
<object data="https://img.shields.io/badge/build-passing-brightgreen?link=https://github.com&amp;link=https://travis-ci.org" type="image/svg+xml">
  <img alt="Build" src="https://img.shields.io/badge/build-passing-brightgreen">
</object>
```

The `<object>` tag renders the interactive SVG with split click targets. The inner `<img>` is a fallback for browsers that do not support `<object>` (though it will only have a single non-clickable image). Note: this works on standalone HTML pages but is **not reliable in GitHub README Markdown**.

### Single-Link Alternative for Markdown

In Markdown, you cannot use split click targets. Instead, wrap the badge image in a standard Markdown link for a single click target covering the entire badge:

```markdown
[![Build](https://img.shields.io/badge/build-passing-brightgreen)](https://github.com/your-repo)
```

### Single-Link Alternative for HTML

```html
<a href="https://github.com/your-repo">
  <img alt="Build" src="https://img.shields.io/badge/build-passing-brightgreen">
</a>
```

## GitHub README Pitfalls & Troubleshooting

### 1. Split Click Targets Don't Work in Markdown

The `link` parameter's left/right split click targets only work inside `<object>` HTML tags. In a GitHub README rendered from Markdown, use an `<img>` wrapped in a link instead. Even if you write raw HTML `<object>` in a `.md` file, GitHub's Markdown sanitizer may strip it.

**Fix:** Use single-link Markdown syntax:

```markdown
[![Badge](https://img.shields.io/badge/...)](https://your-link.com)
```

### 2. `logoWidth` Is Removed — Don't Use It

Many Stack Overflow answers and blog posts from 2021-2024 reference `logoWidth`, but it was removed from Shields.io. Using it will silently have no effect.

**Fix:** Use `logoSize=auto` for adaptive resizing, or pre-size your custom SVG before base64-encoding it.

### 3. Link Target URL Contains `&` or `?`

If a `link=` target URL itself contains query parameters with `&`, those `&` characters will be interpreted by Shields as additional badge query parameters, breaking the link.

| Wrong | Right |
|---|---|
| `?link=https://example.com?a=1&b=2` | `?link=https://example.com?a=1%26b=2` |

**Fix:** The critical character to encode is `&` as `%26` within link target URLs. If you need full safety, URL-encode the entire target URL (e.g., `https%3A%2F%2Fexample.com%3Fa%3D1%26b%3D2`).

### 4. Forgetting to URL-Encode Spaces and Special Characters

In the path segment, a raw space breaks the URL. Use `_` for spaces (which renders as a space) or `%20`.

| Wrong | Right |
|---|---|
| `badge/my project-blue` | `badge/my_project-blue` or `badge/my%20project-blue` |

### 5. Using `#` in Hex Colors Without Encoding

A raw `#` in a URL is interpreted as a fragment identifier and truncates the query string.

| Wrong | Right |
|---|---|
| `?color=#007ec6` | `?color=007ec6` (omit `#`) or `?color=%23007ec6` (encode it) |

### 6. Assuming Shields Named Colors Match CSS Named Colors

Shields `orange` is `#fe7d37`, but CSS `orange` is `#ffa500`. They are different. If you need a CSS-exact color, use the hex value directly.

### 7. `logoColor` Not Working on Custom Logos

`logoColor` only applies to Simple Icons named logos. It has no effect on custom base64 logos. To recolor a custom logo, edit the SVG's `fill` attribute before encoding it.

### 8. Base64 Logo Too Long

The total request header is limited to 8192 bytes. If your base64 string is too long, the badge request will fail.

**Fix:** Optimize and minify your SVG before encoding. Remove metadata, comments, and unnecessary attributes using [SVGOMG](https://jakearchibald.github.io/svgomg/).

### 9. `+` Not Encoded in Data URIs

In `data:image/svg+xml`, the `+` must be URL-encoded as `%2b` in the query string. An unencoded `+` may be interpreted as a space.

| Wrong | Right |
|---|---|
| `logo=data:image/svg+xml;base64,...` | `logo=data:image/svg%2bxml;base64,...` |

### 10. Double Dashes Creating Unintended Splits

Since `--` encodes a literal dash, using `--` in your label or message will produce a `-` in the output, which may not be what you intended. For example, `badge/foo--bar-blue` renders as `foo-bar` in blue, not `foo--bar`.

**Fix:** Use `_` (underscore) for spaces and `--` only when you want a literal hyphen.

### 11. Markdown Image Syntax Inside a Link

When wrapping a badge in a link, the image syntax must be inside the link brackets. A common mistake is putting the URL on the wrong side:

| Wrong | Right |
|---|---|
| `![text](badge-url)(link-url)` | `[![text](badge-url)](link-url)` |

### 12. Cache Not Updating After Changing Badge URL

Shields.io caches badges server-side. If you change a badge's parameters and it doesn't update, the old version may be cached. The `cacheSeconds` parameter can set a minimum cache lifetime, but values below Shields' default are ignored.

**Fix:** Wait for the Shields and GitHub cache to expire, or change the badge URL or content (e.g., tweak a label or color). Do not rely on `cacheSeconds=0` to force a refresh — the docs state that values below Shields' inferred default are ignored. Note that GitHub also caches images in its proxy, so it may take additional time for README badges to refresh.

### 13. Social Style Renders Differently Than Expected

The `social` style renders the label in dark text on a light background, not the typical left-dark / right-colored split. It is designed to look like social media follow buttons, not status badges. If you want the standard look, use `flat` or `flat-square`.

### 14. GitHub Markdown Sanitizes Raw HTML

GitHub's Markdown renderer sanitizes most HTML. While `<img>`, `<a>`, and `<object>` tags are generally allowed, complex nesting or unsupported attributes may be stripped. Always test your badge in a rendered README preview.

| Tag | Works in GitHub `.md`? |
|---|---|
| `<img src="badge-url">` | Yes |
| `<a href="..."><img src="badge-url"></a>` | Yes |
| `<object data="badge-url" type="image/svg+xml">` | No — stripped or neutered by GitHub's sanitizer; split `link=` targets will not work |
| `<embed>` / `<iframe>` | No (stripped) |

#### Syntax Formatting Rules:
* **Spaces:** Replace spaces with `%20` or an underscore (`_`).
* **Dashes (`-`):** Use two dashes (`--`) if you want a literal dash inside the text.
* **Colors:** Use named colors (e.g., `blue`, `red`, `brightgreen`, `yellow`) or Hex codes (e.g., `007ec6`).

### Making Badges Clickable

If you want a badge to link to an external page (e.g., clicking the License badge takes the user to the license file), wrap the Markdown image syntax inside a link:

```markdown
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow)](./LICENSE)
```
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow)](./LICENSE)

### Customization Options

You can add query parameters to customize the visual style:

* **Style (`?style=`):** Options include `flat` (default), `flat-square`, `plastic`, `for-the-badge`, or `social`.
* **Icons (`?logo=`):** Add brand icons from [Simple Icons](https://simpleicons.org/).

**Example with square style and an icon:**
```markdown
![Python](https://img.shields.io/badge/Python-3.10-blue?style=flat-square&logo=python)
```
