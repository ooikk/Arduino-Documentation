# 1.8" TFT SPI Display - ST7735S

## What is a TFT screen?

A TFT screen is one of the types of displays we can use in electronics and Arduino projects. The size of these screens generally ranges from 1.44" to 3.2" and resolutions from 128x128 to 240x320 pixels.

Within the realm of home electronics, several TFT display models and drivers are available. Common examples include the ST7735 for sizes up to 120x160 pixels and the ILI9341 for sizes up to 240x320 pixels. Other drivers include the ILI9163C, the HX8357 (320x480px), and the Samsung S6D02A1 (QDTech).

In most cases, communication with the TFT screen is done via the SPI bus due to the high volume of data required. Therefore, they are easy to connect and use with Arduino.

Many of the available models include an SD or micro SD card reader, accessible via the SPI bus, which can be used to store images to be displayed on the TFT screen. There are also more expensive models that include a touch panel. If you're considering a touch panel, you should definitely look for a more powerful option.

## How does a TFT screen work?

A TFT display (Thin-Film Transistor Liquid Crystal Display) is an active-matrix LCD screen. It uses tiny transistors built directly into the screen’s pixels to control them individually. This technology allows for faster response times, sharper images, and much better color accuracy than older passive-matrix screens.

TFT screens are a variation of LCD (Liquid Crystal Display) screens. In general terms, an LCD is a glass panel that becomes opaque , and its opacity is electrically controlled.

LCD panels do not generate their own light; they require a backlight provided by a light source (such as fluorescent or LED). The LCD panel blocks the emitted light at certain points, allowing an image to be generated.

Here is the translation of the pin label to standard SPI terminology:

```
SCL -> SPI SCK (Serial Clock)
SDA -> SPI MOSI (Serial Data In / Master Out Slave In)
RST -> Reset (Hardware reset pin)
DC  -> Data/Command select (Sometimes labeled as RS or A0)
CS  -> Chip Select (Active LOW to enable the display)
BLK -> Backlight control (Can be tied to VDD or driven via PWM to control brightness)
```

Driving 128 x 160 color pixels requires pushing a massive amount of data compared to a tiny 128 x 64 monochrome OLED. If this were running over typical 400kHz I2C, the refresh rate would be painfully slow—essentially a slideshow. SPI allows you to crank the clock speed up to 15 to 30 MHz (or higher, depending on your microcontroller), giving you smooth rendering.

If you are setting this up with an ESP32-S3 using libraries like TFT_eSPI or Adafruit_ST7735, you will just map your chosen hardware SPI pins to SCL (Clock) and SDA (MOSI), and allocate three free GPIOs for RST, DC, and CS.

## Library

There are two primary libraries used to drive the ST7735 1.8" TFT display, each catering to different performance needs and controller types.

**1. The Standard Choice: Adafruit ST7735 & GFX**

This is the most common and "plug-and-play" option for Arduino users. It is well-documented but can be slower on more advanced microcontrollers like the ESP32.  

**- Required Libraries:** You must install both the "Adafruit ST7735 and ST7789 Library", the "Adafruit GFX Library" and "Adafruit BusIO" via the Arduino Library Manager.  
**- Initialization:** These displays often have a colored physical tab (black, green, or red) on the screen protector which indicates the specific software "initializer" needed (e.g., INITR_BLACKTAB) to fix color inversion or pixel offsets.

Insatll libraries by Adafruit:
1. Adafruit GFX Library   
https://github.com/adafruit/Adafruit-GFX-Library

2. Adafruit ST7735 and ST7789 Library   
https://github.com/adafruit/Adafruit-ST7735-Library

3. Adafruit BusIO   
https://github.com/adafruit/Adafruit_BusIO


**2. The Performance Choice:**

**TFT_eSPI**    
If you are using an ESP32 or ESP8266, TFT_eSPI is highly recommended because it is significantly faster than the Adafruit libraries.  

**Optimization:** It uses hardware-specific optimizations and DMA (Direct Memory Access) to achieve much higher frame rates.  
**Setup:** Unlike Adafruit's library, this requires you to manually edit a **User_Setup.h** file within the library folder to define your display driver (#define ST7735_DRIVER) and pin connections before it will work.  

TFT_eSPI by Bodmer  
https://github.com/Bodmer/TFT_eSPI

## Code Initialization for Adafruit Library

```
#include <Adafruit_GFX.h>     // Core graphics library
#include <Adafruit_ST7735.h>  // Hardware-specific library for ST7735
#include <Adafruit_ST7789.h>  // Hardware-specific library for ST7789
#include <SPI.h>

// Pin definitions for ESP32 S3
#define TFT_CS 10
#define TFT_RST 9
#define TFT_DC 14
#define TFT_MOSI 11
#define TFT_SCLK 12

// For ST7735-based displays, we will use this call
Adafruit_ST7735 tft = Adafruit_ST7735(TFT_CS, TFT_DC, TFT_MOSI, TFT_SCLK, TFT_RST);

// Use this initializer if using a 1.8" TFT screen:
   tft.initR(INITR_BLACKTAB);      // Init ST7735S chip, black tab

// OR use this initializer if using a 1.8" TFT screen with offset such as WaveShare:
// tft.initR(INITR_GREENTAB);  // Init ST7735S chip, green tab

// SPI speed defaults to SPI_DEFAULT_FREQ defined in the library, you can override it here
// Note that speed allowable depends on chip and quality of wiring, if you go too fast, you
// may end up with a black screen some times, or all the time.
//tft.setSPISpeed(40000000);
```

## Code Initialization for TFT_eSPI Library

If you are using TFT_eSPI, you must define these pins inside your User_Setup.h file. Uncomment and edit the following lines:

```
// Section 1
#define ST7735_DRIVER      // Define additional parameters below for this display

#define TFT_WIDTH  128
#define TFT_HEIGHT 160

#define ST7735_BLACKTAB

// Section 2
#define TFT_MISO -1
#define TFT_MOSI 11
#define TFT_SCLK 12
#define TFT_CS   10  // Chip select control pin
#define TFT_DC   14  // Data Command control pin
#define TFT_RST   9  // Reset pin (could connect to RST pin)

// Section 4
#define USE_HSPI_PORT

```
Initialize in the ino, example below display simple text output.

```
#include <TFT_eSPI.h>
#include <SPI.h>

TFT_eSPI tft = TFT_eSPI();

void setup() {
  Serial.begin(115200);

  tft.init();
  tft.setRotation(1);  // Landscape
  tft.fillScreen(TFT_BLUE);

  tft.setTextColor(TFT_WHITE, TFT_BLUE);
  tft.setTextSize(2);
  tft.setCursor(10, 10);
  tft.println("ESP32-S3 OK!");
  Serial.println("Press <SEND> (or type a character) to advance");
  while (!Serial.available())
    ;
  //Serial.read();
}

void loop() {
  tft.fillScreen(TFT_RED);
  delay(1000);
  tft.fillScreen(TFT_GREEN);
  delay(1000);
  tft.fillScreen(TFT_BLUE);
  delay(1000);
}

```

Text rendering offers several customization options:
```

tft.setTextWrap(true);                          // Enable line wrapping

tft.println(text);                              // print text with line feed
tft.drawString("text", x, y, font_number)       // Draws text at specific coordinates.
tft.drawCentreString("text", x, y, font_number) // Centers text horizontally at x.

The default font uses 5×7 pixel characters at size 1, scaling linearly with larger sizes.
```

**RGB565 Format**

Instead of the standard 24-bit RGB (8 bits per color = 3 bytes), RGB565 uses:
- Red: 5 bits (0-31)
- Green: 6 bits (0-63)
- Blue: 5 bits (0-31)
Total: 16 bits = 2 bytes (saves 33% memory!)   

The bit layout is: RRRRRGGGGGGBBBBB   
Breaking Down Examples:   
TFT_BLUE = 0x001F

```
Hex:     0x001F
Binary:  00000000 00011111
         ──┬── ──┬───┬─
           │     │   └─ Blue (5 bits)   = 11111 = 31 (max)
           │     └─ Green (6 bits)      = 000000 = 0
           └─ Red (5 bits)              = 00000 = 0
Result:    Pure Blue
```
TFT_GREEN = 0x07E0

```
Hex:     0x07E0
Binary:  00000111 11100000
         ──┬── ──┬────
           │     │   └─ Blue (5 bits)   = 00000 = 0
           │     └─ Green (6 bits)      = 111111 = 63 (max)
           └─ Red (5 bits)              = 00000 = 0
Result:    Pure Green
```

Conversion Formula:
To convert 8-bit RGB (0-255) to RGB565:
```
// From 24-bit to 16-bit
uint16_t color565 = ((red   >> 3) << 11) |  // 8-bit → 5-bit, shift to bits 11-15
                    ((green >> 2) << 5)  |  // 8-bit → 6-bit, shift to bits 5-10
                    (blue  >> 3);           // 8-bit → 5-bit, stays in bits 0-4
```
Example for pure blue (0, 0, 255):

```
red   = 0   >> 3 = 00000 (0)
green = 0   >> 2 = 000000 (0)
blue  = 255 >> 3 = 11111 (31)

Result: 00000 000000 11111 = 0x001F
```
Why RGB565?
TFT displays like the ST7735 use RGB565 because:  
Saves memory: 2 bytes per pixel instead of 3  
Faster transfers: Less data to send over SPI  
Good enough: 65,536 colors vs 16.7 million (human eye can't tell the difference for most applications)  
The comment /* 0, 0, 255 */ in your code is just showing the equivalent 8-bit RGB value for reference, not the actual storage format!
