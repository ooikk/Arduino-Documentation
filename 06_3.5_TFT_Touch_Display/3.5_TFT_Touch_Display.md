## Connect ILI9488 to ESP32 S3   

Most 3.5" ILI9488 SPI modules have a built-in 3.3V voltage regulator, meaning you can safely power the VCC pin with 5V or 3.3V. However, the logic signals (MOSI, SCK, DC, RST, CS) are strictly 3.3V. Fortunately, the ESP32-S3 natively outputs 3.3V logic, making them directly compatible.

Connecting the Touch (XPT2046) and SD Card modules alongside the ILI9488 display is very common, as most 3.5" modules have all three built onto the same PCB.
The key concept here is the Shared SPI Bus. The Display, Touch, and SD Card all share the same Clock (SCK), MOSI, and MISO lines. They are differentiated by their individual Chip Select (CS) pins. Only the device whose CS pin is pulled LOW will listen to or drive the shared bus.
Here is the complete guide to wiring and configuring all three.

**The ILI9488 Hardware Bug (Crucial Warning)**  
The SDO / MISO pin on an ILI9488 driver fails to release the SPI bus (it does not enter a high-impedance tri-state) even when the display's TFT_CS is high. If you wire the screen’s SDO / MISO pin directly to the same bus as the Touch and SD card, it will block the SD card and touch controller from talking to the ESP32-S3, causing them to fail.

**How to Correctly Wire the Shared SPI Bus**    
To bypass the hardware bug, disconnect the screen's MISO pin entirely (the screen doesn't need it to display graphics). Tie the Touch and SD card MISO pins together instead.

```
ILI9488 Pins    ESP32 S3 Pins      Description

***Display Pins***

VCC	            3.3V               Connect to external 3.3V, it may overheat the ESP32 regulator!!
GND	            Gnd                Common ground external power supply and ESP32
CS	            GPIO 9             Unique CS
RESET           GPIO 10
DC/RS           GPIO 14
SDI(MOSI)       GPIO 11            Shared MOSI pin
SCK             GPIO 12            Shared Clk pin
LED	            3.3V/ GPIO x       Backlight control, optional using PWM
SDO(MISO)       NC                 Do not connect

***Touch Pins***

T_CLK           GPIO 12            Shared Clk pin
T_CS            GPIO 8             Unique CS
T_DIN           GPIO 11            Shared MOSI pin
T_DO            GPIO 13            Shared MISO pin

***SD Card Pins***

```

## Enable Interrupt pin

The TFT_eSPI library does not natively support or use the T_IRQ interrupt pin. Its internal touch handler (tft.getTouch()) relies entirely on polling, meaning the ESP32-S3 constantly queries the touch chip over SPI to check if it has been pressed.

However, you can easily set up hardware interrupts by writing an Arduino hardware interrupt function (attachInterrupt) for the T_IRQ pin.

The layout below establishes how to configure this on your ESP32-S3.

**Step 1: Physical Wiring Setup**   
The T_IRQ pin on an XPT2046 touch controller is an "active LOW" open-drain signal. It rests at HIGH (3.3V) and drops to LOW (0V) the exact moment a touch is detected.
- Connect T_IRQ on your display board to GPIO 5 (or any free input-capable GPIO) on the ESP32-S3.

**Step 2: Leave User_Setup.h Alone**   
Do not try to define T_IRQ inside your TFT_eSPI config files. The library will ignore it. Keep only your standard configurations active, such as:
```
#define TOUCH_CS 4  // Ensure your Touch Chip Select is active
```
**Step 3: Implement the ESP32 Code**   
To prevent the SPI bus from crashing, never perform SPI reading tasks inside an Interrupt Service Routine (ISR).   
Instead, use the interrupt strictly to trigger a boolean flag, and then read the touch coordinates safely inside your core loop() structure:   
```
#include <SPI.h>
#include <TFT_eSPI.h>

TFT_eSPI tft = TFT_eSPI();

// Define the Touch Interrupt Pin
const int TOUCH_IRQ_PIN = 5; 

// Volatile flag changes inside the interrupt loop
volatile bool touchDetected = false;

// 1. The Interrupt Service Routine (ISR)
// Runs instantly when the screen is physically pressed
void IRAM_ATTR touchISR() {
  touchDetected = true; 
}

void setup() {
  Serial.begin(115200);
  
  // Initialize Screen
  tft.init();
  tft.setRotation(1);
  
  // Configure the Interrupt Pin
  // INPUT_PULLUP keeps the pin stable when the screen isn't touched
  pinMode(TOUCH_IRQ_PIN, INPUT_PULLUP); 
  
  // Attach interrupt: Triggers on FALLING edge (HIGH to LOW transition)
  attachInterrupt(digitalPinToInterrupt(TOUCH_IRQ_PIN), touchISR, FALLING);
  
  Serial.println("Interrupt setup complete. Tap screen to test...");
}

void loop() {
  // If the flag was raised by the hardware interrupt
  if (touchDetected) {
    
    uint16_t x = 0, y = 0;
    
    // Query the SPI bus for coordinates safely outside the ISR
    if (tft.getTouch(&x, &y)) {
      Serial.printf("Touch detected via Interrupt! X: %d, Y: %d\n", x, y);
    }
    
    // Clear the flag to wait for the next interrupt cycle
    touchDetected = false;
    
    // Add a tiny debounce delay to avoid spamming the bus
    delay(50); 
  }
}

```
**Pro-Tip for Shared SPI Buses**   
Because the display, SD Card, and touch chip share your ESP32-S3 SPI bus, they take turns pulling their respective Chip Select (CS) pins low.   
Using the interrupt methodology outlined above ensures that the ESP32-S3 only opens an SPI transaction with the touch controller when a physical hand press pulls T_IRQ down, maximizing your overall frame rate and rendering performance.

## Activating the SD Card   

In your Arduino IDE code, you can initialize the SD card reader simultaneously alongside your display. Ensure you pass your custom SD_CS pin 7 to the initialization function:   

```
#include <SPI.h>
#include <SD.h>
#include <TFT_eSPI.h>
#define SD_CS_PIN 7

TFT_eSPI tft = TFT_eSPI();

void setup() {
  Serial.begin(115200);
  
  // Initialize the TFT display
  tft.init();
  tft.setRotation(1);
  
  // Initialize the SD Card using the shared SPI bus
  if (!SD.begin(SD_CS_PIN)) { 
    Serial.println("SD Card initialization failed!");
  } else {
    Serial.println("SD Card ready!");
  }
}

void loop() {}

```
## Combined Test Sketch (Display + Touch + SD)   

This sketch initializes the display, checks if the SD card is present, and prints a basic touch prompt.
***Note: You will need a microSD card formatted as FAT32 inserted into the module for the SD test to pass.***

```
#include <TFT_eSPI.h>
#include <SPI.h>
#include <SD.h>

TFT_eSPI tft = TFT_eSPI();

// Define the SD Chip Select pin (must match wiring)
#define SD_CS_PIN 7

void setup() {
  Serial.begin(115200);
  
  // 1. Initialize Display
  tft.init();
  tft.setRotation(1); // Landscape
  tft.fillScreen(TFT_BLACK);
  tft.setTextColor(TFT_WHITE, TFT_BLACK);
  tft.setTextSize(2);
  tft.setCursor(20, 20);
  tft.println("Initializing...");

  // 2. Initialize SD Card
  tft.setCursor(20, 60);
  tft.print("SD Card: ");
  
  // SPI transactions ensure the SD library doesn't conflict with TFT_eSPI
  if (!SD.begin(SD_CS_PIN)) {
    tft.setTextColor(TFT_RED, TFT_BLACK);
    tft.println("FAILED");
    Serial.println("SD Card initialization failed!");
  } else {
    tft.setTextColor(TFT_GREEN, TFT_BLACK);
    tft.println("OK");
    Serial.println("SD Card initialized successfully.");
    
    // Optional: Print SD card capacity
    uint8_t cardType = SD.cardType();
    if(cardType == CARD_NONE){
        tft.println("No SD card attached");
    } else {
        uint64_t cardSize = SD.cardSize() / (1024 * 1024);
        tft.print("Size: ");
        tft.print(cardSize);
        tft.println(" MB");
    }
  }

  // 3. Touch Prompt
  tft.setTextColor(TFT_WHITE, TFT_BLACK);
  tft.setCursor(20, 120);
  tft.println("Touch screen to");
  tft.println("test coordinates.");
}

void loop() {
  // Check for touch
  uint16_t x = 0, y = 0;
  bool touched = tft.getTouch(&x, &y);

  if (touched) {
    Serial.printf("Touch detected: X = %d, Y = %d\n", x, y);
    
    // Clear a small area and print the coordinates on screen
    tft.fillRect(20, 160, 200, 30, TFT_BLACK);
    tft.setCursor(20, 160);
    tft.printf("X: %d  Y: %d", x, y);
    
    delay(100); // Debounce
  }
}
```
